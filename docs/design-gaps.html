Sweep: architecture

13 · not on any roadmap stage

Gaps between the parts. The pipeline itself is covered in docs/architecture.html, so these are what's still missing around it: how parts connect, stay correct and stay safe.

X1

How the app reads the index

Nothing sits between the UI and SQLite. A browser can't load a 412 MB file, and the app, Ask and MCP each need time-sliced graph queries. Decide on one query service, either cartograph open serving an API and the app, or SQLite in WebAssembly, and route all three through it.

Blocks stage 3. It is also the open decision in PRODUCT.md.

HighOpen
X2

Prompt injection from indexed code

Comments, READMEs and commit messages flow into model prompts through retrieval, and any of them can carry instructions. Wrap every retrieved span as data, limit the agent to read-only graph tools, and never run anything an answer suggests. Checking citations doesn't cover this.

HighOpen
X3

Branches and pull requests

The indexer walks first-parent history of the default branch only. Commit impact for a PR (A5) needs the branch indexed on top of its base, without changing the main timeline.

HighOpen
X4

Updating without push events

Settled: with no server, there are no webhooks. S3 offers every hour, only when you run it, or after each commit or pull through a local git hook.

MediumSettled
X5

Reading while the indexer writes

Use WAL mode and snapshot reads, write updates to a temp file and swap it in atomically, and have the app notice the new version. Otherwise the map can show half an update.

MediumOpen
X6

File formats are contracts too

The index, cartograph.yaml and the override file each need a versioned schema, a validator, migrations and a compatibility table between CLI and app. Board 02 shows the error, but nothing plans the upgrade.

MediumOpen
X7

Overrides that survive renames

Overrides refer to paths, so they break silently when a file moves. Key them by lineage id, flag ones that no longer match anything, and write down which source wins: parsed, then contract, config, runtime, override.

MediumOpen
X8

A plugin interface for extractors and adapters

S5 says "request an adapter". Without a published fact schema and a plugin interface, run as a subprocess or in WebAssembly, every new framework needs a core release.

MediumOpen
X9

Generated API clients

A2 and S1 count calls through a generated SDK. Matching them needs codegen detection that maps each generated method to its operationId. URL matching can't see through them.

MediumOpen
X10

Stale derived data

Summaries, embeddings, concepts and reachability go stale when code, models or extractors change. Record each derived row's inputs (blob ids, model id, extractor version) and rebuild only what changed.

MediumOpen
X11

Architecture rules

Leads want to declare constraints, such as layers, forbidden dependencies and no cycles, and have every commit and CI run check them. The graph can answer this, but nothing in the plan asks it to.

MediumOpen
X12

Reproducible indexes

The same commits should give a byte-identical index, so a teammate or a CI job building from the same manifest gets the same file, and can check that it matches.

LowOpen
X13

Errors from the field

There's no error reporting, and nothing may leave the machine. When an extractor fails on real code, the tool should write a local report, with the code left out, that a person can choose to attach to an issue.

LowOpen

Sweep: design

15 · across the canvas
D1

The rest of the add-workspace wizard

Only step 2 of 4 is drawn. Steps 1 (pick sources), 3 (review services) and 4 (first index, then the map) are missing, along with what happens when discovery finds nothing.

HighOpen
D2

First run offers only the CLI

Board 01 predates the in-app wizard. It should offer three ways in: add a workspace in the app, open an index file, or try the demo.

HighOpen
D3

A way to read the map without seeing it

The map is SVG and WebGL, which screen readers can't use. It needs a table view of nodes and links with the same filters and date, and a keyboard walk through nodes that announces each node's name and link counts.

HighOpen
D4

One app shell

The G boards lack the view tabs added in the A boards, and board 15's settings menu differs from the S boards'. Pick one header and one settings menu.

MediumOpen
D5

Notifications and activity

An index that finished or failed, a token about to expire, a new breaking change: nothing says where these appear. They need toasts plus an activity list.

MediumOpen
D6

The map after "Trace on the map"

A2 and A5 send you to the map, but the map state they land on isn't drawn: the reachable set highlighted, the rest dimmed, and a way to clear it.

MediumOpen
D7

Compare two points in time

Leads review drift between two releases. Scrubbing shows one date at a time. They need a compare mode: two dates, what coupling was added or removed, and the map coloured by the difference.

MediumOpen
D8

Architecture rules view

The UI for X11: a list of rules, current violations, and pass or fail for each commit.

MediumOpen
D9

Share and export

A cartograph:// link that reopens the same node, layout, date and filters in a teammate's local app, plus PNG and SVG export of the map for design reviews.

MediumOpen
D10

Recovery flows

Renew an expiring token, fix a failed spec URL, undo a correction, and see who changed the override file and when. S2 and board 09 show the problems but not the way out.

MediumOpen
D11

Commit impact inside the pull request

Paired with X3: cartograph impact prints a branch's impact as Markdown, so a CI step the team runs itself can post it as a comment. Cartograph never posts anything on its own.

MediumOpen
D12

The CLI's own output

The CLI is most people's first contact. It needs designed progress output, errors that name the fix, a coverage summary after each run, and --json for CI.

MediumOpen
D13

DESIGN.md is behind the canvas

The theme tokens, theme rules, chip states, view tabs, settings menu and pending colour rule exist only on boards. Write them back so the code has one source.

MediumOpen
D14

Owners and teams

CODEOWNERS is indexed, but no view shows who owns what or which teams depend on each other.

LowOpen
D15

Ask history

Past questions, saved questions, and re-running a question as of another date.

LowOpen
