Cartograph · spec, revised 21 Nov 2026

Command line, MCP server and agent setup

How a workspace gets its first index, how the index stays current, and how coding agents such as Claude Code and Cursor read it. Cartograph runs only on this machine, so every operation here is a local command or a local MCP tool. Nothing here needs a server.

The reasons for each choice, with open-source precedents, are in the decision record. Ids like B1 point to it.

Ground rules

apply to every command and tool
Local onlyNo network calls of its own. git fetch runs only with --fetch. Ask calls only the model provider you configure.
Git repos onlyA folder that isn't inside a git work tree is listed as skipped, with the reason. It's never indexed.
The workspace file is the inputCartograph reads the folders listed in a .code-workspace file, the same file VS Code and Cursor open.
One binary, one indexThe app, the CLI, MCP and Ask all read the index through one query layer in the cartograph binary. Only one process writes to it at a time.
Answer now, catch up afterEvery read answers straight away and says how far behind each repo is. If one is behind, it starts a sync in the background (D1).

1 · Reading a .code-workspace file

C1 – C6

A .code-workspace file is JSON that allows comments and trailing commas (JSONC). Cartograph parses it exactly the way VS Code does, with the jsonc-parser crate. Only folders decides what gets indexed, and one key in settings is also read. Everything else in the file is ignored.

Where it looks

Cartograph looks for *.code-workspace files in the folder you give it and up to two levels below. It skips node_modules, .git and hidden folders. If it finds more than one, it asks which to use, or you can name one with --workspace.

folders[].path

A relative path is resolved from the folder that holds the workspace file, not from where you ran the command. An absolute path is used as it is. ~ and ${env:…} are not expanded, because VS Code doesn't expand them either. doctor warns about them.

folders[].uri

Only file: URIs are accepted. Any other scheme points to a folder on another machine, so it's skipped with that reason. If the file sets remoteAuthority, the whole workspace is remote and the file is skipped.

folders[].name

Becomes the display name for that repo or scope. Without it, the folder's own name is used. Duplicate folders are removed.

Git check

Each folder must be inside a git work tree (git rev-parse --show-toplevel). A folder inside a repo becomes a scope of that repo. Several folders in one repo make one repo with several scopes, and its history is walked once. Worktrees of the same repo are grouped by --git-common-dir. Shallow clones are marked as shallow, and bare repos are skipped.

settings["files.exclude"]

Paths that match are left out of the index. search.exclude is ignored, because it hides files from search and doesn't mean they aren't code.

No workspace file

Cartograph walks up to three levels down, respecting .gitignore, and stops at each repo it finds. It never follows symlinks. init then offers to save the result as acme.code-workspace, so VS Code and Cursor open the same set of repos.

Default branch

Checked in this order: default_branch in cartograph.yaml, then origin/HEAD, then init.defaultBranch, then main or master, then the current branch with a warning. None of these touches the network.

Services

To split a monorepo into services, the first match wins: cartograph.yaml, then Backstage catalog-info.yaml, then workspace manifests (pnpm, npm, go.work, Nx, Cargo, Composer). A package with a Dockerfile, a k8s Deployment or a Procfile counts as a service rather than a library. If nothing matches, each repo is one service.

cartograph.yaml

init writes this file, and it's meant to be committed. It records the resolved repos with their remotes, their branches, any services, the rules and the options. It has version: 1 and a JSON Schema, so editors can validate it. A teammate who runs cartograph init on it builds an index with the same fact hash (cartograph verify). If the workspace folder isn't a repo, init suggests keeping the workspace file and this manifest in one of the repos, using ../ paths to the others.

Agent setup, per user by default
claude mcp add --scope user · ~/.cursor/mcp.json · ~/.codex/config.toml · VS Code user mcp.json

Everything Cartograph keeps is in one folder, ~/.cartograph, on every platform, so it's easy to inspect, back up or delete. The index is kept out of the workspace folder because that folder often sits inside iCloud Drive, Dropbox or OneDrive, and a sync client can corrupt a SQLite file that's open in WAL mode. You can set index_path to put it somewhere else, but a path inside a synced folder is refused, with the reason. init adds CARTOGRAPH.md to .gitignore, after asking.

4 · Commands

every command takes [dir], defaulting to the current folder

A command run inside any repo of a workspace finds that workspace through the registry. That's why agent config can say just cartograph mcp, with no path.

First index and keeping it current

cartograph init--workspace <file> · --no-index · --hooks · --agents · --yes

Finds the workspace file, resolves and checks each folder, and shows what it will index and what it will skip. Then it writes cartograph.yaml, builds the first index, writes CARTOGRAPH.md and records the workspace in the registry. Before touching .gitignore, hooks or agent setup, it shows the change and asks (E3). Without a terminal and without flags, it writes only the manifest and prints the next commands.

Running it again on a workspace that's already set up is safe. It updates what changed instead of starting over, and tells you so.

cartograph sync--fetch · --wait · --quiet · --background

Indexes only the commits added since the last run, on each repo's indexed branch. It also picks up folders added to or removed from the workspace file. If history was rewritten, it replays from the merge base. If another sync is already running, this one sets a flag and exits 0, and the running sync does one more round (D2). You rarely need to run it yourself, because reads start it in the background.

cartograph status--json · --check

Shows each repo's indexed commit, its HEAD, how many commits it's behind, whether it has uncommitted changes, and whether a sync is running. With --check it exits 3 when anything is behind.

cartograph index --rebuild

Builds the index again from nothing. It asks first and says how long it will take, about 40 minutes on acme. It writes a new file and renames it into place, so the old index stays readable until the new one is complete.

cartograph verify[other index | --manifest]

Compares fact hashes, to show whether two indexes, or an index and a manifest, describe the same facts (B4).

Optional ways to stay current

cartograph hooks installremove · status

Adds hooks for post-commit, post-merge, post-checkout and post-rewrite, each running cartograph sync --quiet --background. On Git 2.54 and later these go in git config (hook.cartograph.*) and run alongside your other hooks. On older Git, Cartograph adds a marked block to an existing shell hook, and otherwise refuses and prints the line to add. If husky or lefthook manages your hooks, it prints a snippet for their config and writes nothing (D3).

cartograph schedule hourlyoff · status

Runs sync --fetch every hour, to pick up what teammates have pushed. This is one user-level job that loops over every workspace in the registry, at a random minute past the hour: launchd on macOS, a systemd user timer on Linux, schtasks on Windows (D4).

Reading the map

cartograph open[cartograph:// link]

Serves the app, which is built into the binary, on 127.0.0.1 at a random port with a session token, then opens it. Given a share link, it opens that view (I7).

cartograph mcp--http · --list

Runs the MCP server over stdio. --http listens only on loopback, checks Host and Origin, and needs the token (F4).

cartograph tool <name> [json]

Runs any MCP tool from the shell and prints its JSON result, so you can see exactly what an agent sees.

cartograph impact <ref>--working-tree · --wait · --format md|json

Prints what a branch, a commit range or your uncommitted changes would affect. A branch is read as an overlay on its base (B5). Your own CI can post the Markdown output. Cartograph never posts anything itself.

cartograph check

Fails if a correction no longer matches anything, or if an architecture rule is broken by a link at min_confidence or above (H3, H6).

cartograph ask "…"--at <date> · --history · --forget

Asks the map a question through the same agent loop the app uses (G3). --forget wipes your Ask history.

Agents, health and cleanup

cartograph agents installremove · status · --project · --per-repo · --shared

Writes MCP config for every agent it finds, at user level by default. For Claude Code it suggests the plugin instead (section 6). It writes the short instruction block only where that agent needs one.

cartograph doctor--fix

Checks:

  • the git version
  • the workspace file, including ~ in paths
  • that each repo can be reached, and whether any are shallow
  • the index format, and whether the index path is inside a synced folder
  • hooks, the schedule's binary path, and agent setup
  • clones of the same repo in more than one folder

Each failure prints the exact command that fixes it. --fix runs only fixes that can be undone.

cartograph report

Writes a report of the last failure to reports/, with paths and code removed. Nothing is sent anywhere.

cartograph clean--cache · --all

Deletes the cache, or with --all the index too. It asks first, and never touches committed files or Ask history.

Exit codeMeaning
0Done, the index is current, or a sync was already running and will cover this request.
1Failed, including when the index format is newer than this CLI. The message names the fix, and cartograph report writes the details.
2Bad arguments, or no workspace found here.
3status --check only: one or more repos are behind.

Output follows clig.dev. Progress goes to stderr and only on a terminal. --json prints a versioned object, {"schema":1,…}. The CLI respects NO_COLOR. Errors say what went wrong, why, and what to try.

5 · MCP tools

F1 – F4 · eight tools

Every result includes freshness: for each repo, the indexed commit, its HEAD, how many commits behind it is, and whether a sync is running. content holds compact Markdown for the model. structuredContent holds the full JSON, with an outputSchema. Lists default to 50 items with a cursor, and each response aims for under 10k tokens. response_format: concise | detailed chooses between them.

Reading readOnlyHint

status

The same data as CARTOGRAPH.md, plus any running jobs, when given a job_id. Agents are told to call it first.

find

Services, modules, files, symbols or entrypoints (kind), by name or path. Results are ranked by fan-in.

describe

A node's description, kind, owner and links. For a contract, its operations and who serves and calls each one. Text that comes from the repo is returned only on request, in untrusted_text fields (F8).

neighbors

Links into or out of a node: direction is callers, callees, deps or dependents, with optional depth, kinds and cross_service.

path

How two nodes connect, with each link's confidence.

impact

Takes paths, a ref, working_tree: true, or since a commit or date. Returns what's affected across services, grouped as exact, likely and guessed. Uncommitted files are parsed in memory and never written to the index.

Operating

syncidempotent

Returns the result if it finishes within wait_ms (15 s by default). Otherwise it returns a job_id to pass to status. It sends progress notifications when the client provides a progress token. When there's no index yet, sync runs init, and in that case it defaults to dry_run: true, returning the folder resolution table from section 1 without writing anything.

correctwrites file

Adds an entry to cartograph.overrides.yaml and returns the diff. It needs a reason, and stores data, never instructions.

The MCP server never runs index --rebuild, clean, hooks or schedule. No tool runs code or uses the network, and sync only acts on repos in the registry. Server instructions are kept under 4,096 characters and never include text from the repos.

6 · Setting up coding agents

F5 · F6 · G1

Agent setup is per user by default, so you don't have to commit anything in N repos and teammates without Cartograph don't get a server that won't start. --project writes config to the workspace folder. --per-repo writes it into every repo.

AgentMCP serverInstructions
Claude CodeThe Cartograph plugin: MCP server, skill, and a SessionStart hook that prints one line about how current the index isThe plugin's skill. Without the plugin, a block in CLAUDE.local.md, or in CLAUDE.md with --shared

Codex and others~/.codex/config.toml → [mcp_servers.cartograph]AGENTS.md block

The block holds pointers only, never state, and doesn't @-import CARTOGRAPH.md. An import would load the whole file into every session, and the state would be out of date before the session ended.

Using Claude Code itself as the model for Ask: Cartograph doesn't build in the Claude Agent SDK and never offers a claude.ai sign-in, because Anthropic's terms don't allow third-party apps to do that. Your own Claude Code uses Cartograph through the plugin instead. An "External agent" option over ACP may come later (G1, G2).

7 · Index states

the state field in CARTOGRAPH.md, status and the app
noneinit →syncing→currentnew commits →behindnext read →syncing→current
StateWhat it meansWhat reads doWay out
noneNo index for this workspace.Tools return an error that names cartograph init. MCP sync offers a dry run.init
currentEvery repo's indexed commit is its HEAD.Answer normally.n/a
behindOne or more repos have newer commits.Answer at once, report how far behind, and start a sync in the background.Happens on its own
syncingThe writer holds the lock.Answer from the snapshot the read started on (WAL).Wait
rewrittenAn indexed commit is gone from the branch, after a force-push or rebase.Answer, with a warning on that repo.sync replays from the merge base
needs-migrateThe index format is older than this CLI.Read-only if the format can still be read, otherwise an error.sync migrates it, or index --rebuild
failedThe last run stopped part way through.Answer from the last complete index.doctor, then sync

The index uses SQLite's WAL mode, so readers keep the snapshot they started with. Only one process writes at a time, under an OS lock on index.lock. The kernel releases that lock if the process dies, so it can never go stale. Only a full rebuild or a migration writes a new file and renames it into place (B2).

8 · Cases to handle

each one gets a clear message, not a crash
Branches and PRs

The timeline covers one branch per repo. impact <ref> and the checked-out branch get an overlay on their base, which costs about as much as the diff and is dropped once the branch merges (B5). status says when HEAD is on a branch other than the indexed one.

Shallow clones

Cartograph indexes the history that's present and marks the repo shallow. The message names git fetch --unshallow.

Detached HEAD

The configured branch is indexed. impact --working-tree still covers whatever is checked out.

Submodules, nested repos

They're indexed only if the workspace file lists them as folders.

Same repo cloned twice

The registry matches repos by remote URL and root commit, and doctor warns.

Repo moved on disk

doctor --fix finds it again by remote URL and root commit, then updates the registry.

Renames

Exact blob matches are tried first, then gix-diff similarity matching (50%, at most 1,000 candidates). The commit is noted when that limit is hit (B7).

LFS, binaries, generated files

LFS pointers, binaries and files over 1 MB are listed but not parsed. Generated API clients are recognised by their headers and matched to their spec (H5).

Two workspaces share a repo

Each workspace has its own index, and they share the parse cache by blob id.

Windows and case

Backslashes in path are accepted. On a file system that ignores case, paths are compared without case before merging.
